## 一个执行现场

浏览器通过 HTTPS/WSS 访问一个 Node 服务。聊天读取原 Codex 记录，输入和按键进入原 tmux；不会额外启动模型。预览分离来源，但复用登录授权。网关与工作机同机时直连回环端口，异机时可增加受限反向 SSH 隧道。

| 模块                                  | 职责                                                     |
| ------------------------------------- | -------------------------------------------------------- |
| `server.mjs`                          | HTTP / WebSocket 路由、精确 Host / Origin 校验、生命周期 |
| `lib/config.mjs`、`preflight.mjs`     | 配置验证、HTML 转义、品牌默认值、凭据检查                |
| `lib/auth.mjs`、`github-auth.mjs`     | 本地会话、密码/TOTP 或 GitHub 单账号认证                 |
| `lib/registry.mjs`                    | 会话白名单、重建身份检测、预览绑定                       |
| `lib/terminal.mjs`、`history.mjs`     | PTY、输入租约、按键与只读历史                            |
| `lib/chat.mjs`、`codex-reader.py`     | 进程关联、只读记录与活动规范化                           |
| `lib/chat-send.mjs`、`chat-input.mjs` | 同线程代送、回执、不确定结果不重放                       |
| `lib/preview*.mjs`、`control.mjs`     | 预览鉴权、资源/媒体、本地绑定入口                        |
| `public/`                             | 原生前端；按需加载终端，活动详情展开后挂载               |

主要接口：`/api/bootstrap`、`/api/sessions`、`/api/sessions/:name/chat`、`/api/sessions/:name/preview`、`/ws`。绑定工具走 owner-only Unix socket，不通过公网暴露管理接口。

## 兼容性，不装作无所不能

聊天适配器目前读取 `state_5.sqlite`、`thread_history_1.sqlite` 及关联的旧版 JSONL。这些不是稳定公开 SDK；合成样例测试通过不代表适配全部 Codex 版本。升级前验证实际版本的线程识别、历史、活动、输入与审批。不支持时明确回到终端，不猜线程、不扫描其他用户。

未接入官方 App Server，不提供跨用户权限管理、完整审计录像或服务端语音识别。切换前端不会更换原 Codex 的模型或安全配置。网页读到的是公开对话和已适配活动，不是私有推理。

## 状态与存储

`config.json` 保存实例参数；`runtime/` 保存身份配置、会话绑定、排序和发送回执（可能包含消息正文）。登录及预览授权在内存，服务重启需要重新登录。tmux 保活不等于主机重建后可恢复进程。

本实例设计为单进程，不要把同一 socket 接到多个 Node 副本。扩展时使用独立 Linux 用户、实例、端口、域名与 Codex 环境；对不互信的用户还需 VM/容器和网络隔离。

## 排错：先找失败层

| 现象           | 先检查                                                 |
| -------------- | ------------------------------------------------------ |
| 整站超时       | 客户端 DNS/路由、错误 AAAA、TLS、防火墙；再查网关      |
| 登录失败       | OAuth 回调、批准的数字 ID、工作机到 GitHub 的连通性    |
| 有网页无会话   | Linux 用户、socket、`allowed`、同名会话是否重建        |
| 聊天无记录     | 原 pane 是否运行 Codex、记录格式/权限；对照原终端      |
| 待核对或未发送 | 检查原终端输入行与回执，不直接重复粘贴                 |
| HTML 慢/打不开 | 预览子域 DNS/TLS、绑定目录、资源大小、硬编码 localhost |
| 语音无文字     | 浏览器权限和识别服务，尝试系统键盘听写                 |

机房 HTTP 200 不代表手机体验。分别测 Wi-Fi/蜂窝、桌面/手机，必要时比较代理开关的路线；不要靠无限重试掩盖网络层失败。

## 更新、备份与撤权

先备份配置和必要运行资料，再以同一 Node 主版本安装依赖、运行测试，在独立实例验证。业务回滚使用上一个源码版本及匹配锁文件，不覆盖用户项目或原 tmux。登录失效是服务重启的预期行为。

加密备份 `config.json` 和 `runtime/`；Codex 历史、项目文件另行管理。恢复到新环境时核对路径与用户，同名会话身份变化需要人工重绑。

撤权先停止该实例/隧道，再撤销专用 OAuth/SSH 凭据；改批准身份后重启清空登录。初始化脚本不会覆盖已有凭据，轮换需先安全保留旧文件、安排停机，再初始化并验收。不要用删除 DNS 代替立即撤权。
